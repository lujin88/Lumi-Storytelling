## 先说结论：这次 review 改变了前提

开发实测出来两件事，Lu 选的方案在现在的架构下做不了，需要 Lu 重新定：

1. **Higgsfield 不能从浏览器直接调用。** 官方文档原话是「Do not call the API directly from browser or mobile application code」(https://docs.higgsfield.ai/docs/authentication.md)。对 `api.higgsfield.ai` 发预检，返回 400，也没有 ACAO。要接 Higgsfield，只能经过一个服务器转发。这就是当初去掉即梦的同一个原因。
2. **火山可以从浏览器调用，但 key 错的时候读不到报错。** 预检能过，可是 401 响应里没有 ACAO，浏览器只拿到 `Failed to fetch`，和断网分不出来。key 对的时候响应里有没有 ACAO，还没用真 key 测过。
3. Higgsfield 的 key 由两段组成（`Key <id>:<secret>`）。官方 openapi 里没有 Seedance，完整的模型目录要登录 console 才能看（待确认）。

## 现有代码里就有的漏洞（和视频无关，今天就存在）

| # | 问题 | 现在的表现 | 建议 |
|---|---|---|---|
| E1 | 校验 key 没有超时 | `fetch` 不带 AbortController。服务商不响应时，这一行会一直停在「检查中」 | 15 秒超时，超时按 `busy` 显示，并保留「重新检查」（秒数待开发实测后定） |
| E2 | 404 被归成 `failed` | 提示「没有通过检查，过一会儿再试」。如果是接口或模型已经停用（比如 Sora），等多久都没用 | 新增 `gone`：「{provider} 停用了这个接口或模型。」并引导去设置换一个模型或换一家服务商 |
| E3 | 403 一律当成 key 错 | 地区限制或账号没有权限时也会提示「不认这个密钥」，用户会一直换 key | 只有 body 里明确写了 invalid key，才判为 `key`。其他 403 新增 `denied`：「{provider} 拒绝了这次请求，可能是地区或账号权限的问题。」 |
| E4 | CORS 被拦和断网显示的是同一句话 | 都是「连不上，检查网络」 | 当 `navigator.onLine` 为真时，改成「连不上 {provider}。检查密钥是否正确，或稍后再试。」不能断定是 key 的问题，就不说是 key 的问题 |
| E5 | 每次打开页面都会按顺序重新校验所有 key | 有 4 家服务商时，打开页面要等好几次请求 | 改成并行校验，每家单独显示状态。视频服务商的校验必须不花钱 |

## 视频引导：每种情况的处理

### 现在就要做的（设置页的「视频」这一行，以及缺 key 时的提示）

| 情况 | 用户看到什么 | 能做什么 |
|---|---|---|
| V1 一家都没连，点了需要视频的功能 | 行内提示：「做视频要先连接一家视频服务。」下面两个按钮：Higgsfield / 火山 | 点其中一个，跳到设置页这一行，并且已经选好这家服务商 |
| V2 选了服务商，但没填 key 就离开了 | 回到原处后，仍然显示 V1 的提示 | 下次进设置时，记住上次选的服务商 |
| V3 连接成功 | 这一行显示「已连接 · {provider}」 | 回到用户原来所在的页面和位置。现在只有 Claude 会跳回去（`firstRunReturn`），需要改成按服务商记住从哪来 |
| V4 两家都填了 key | 这一行只有一个当前服务商，用下拉框切换。另一家的 key 保留，不删除 | 切换之后重新校验当前这家 |
| V5 key 错 | 行内一行报错（PRD 8.12）。火山读不到 401 时，按 E4 的那句话显示 | 重新粘贴 key |
| V6 Higgsfield 要填两段 | 两个输入框：Key ID 和 Secret，或者一个框里粘贴 `id:secret` 再自动拆开 | 少填一段时直接在行内提示，不发请求 |
| V7 校验时把 key 改了 | 已经处理：返回结果和当前 key 对不上就丢弃（`connectProvider` 里的 key-changed 判断） | — |
| V8 双击 `file://` 打开页面 | key 不会保存（现有规则）。来源是 `null`，火山的 CORS 未必放行 | 提示从 4317 打开（沿用现有的 `open_from_server` 思路） |
| V9 额度用完、被限流、服务商没响应 | 沿用 `credit` / `rate` / `busy` | — |
| V10 接口或模型停用了（404） | 按 E2 处理 | 去设置换模型或换服务商 |
| V11 地区或账号权限被拒（403） | 按 E3 处理。火山（国内）和 BytePlus（海外）的 key 不能混用，填错地区也会走到这里 | 提示检查地区，或者换一家 |

### 做「生成视频」时才需要的（目前在 Backlog，先记下，现在不做）

| 情况 | 要定的事 |
|---|---|
| G1 每次生成都花用户自己的钱 | 生成前要不要先确认？价格只写文档里查得到的，查不到就不写 |
| G2 连点或重复提交 | 第一次点击后按钮马上禁用，避免重复扣费 |
| G3 生成要几十秒到几分钟 | loading 要显示进度或已等待的时间。用户离开这一页、刷新、关掉页面之后任务怎么办（任务 id 要存下来，回来后接着查） |
| G4 取消 | 服务商那边能不能取消，取消了还扣不扣费，要查文档 |
| G5 返回的视频链接会过期 | 生成后马上存到 IndexedDB。现在上传的视频刷新就没了（PRD「Persist uploaded videos」在 Backlog） |
| G6 内容审核没通过 | 新增 `moderation`：「{provider} 没有生成这段视频（内容审核）。」引导改一下描述 |
| G7 当前服务商失败，另一家已经连上 | 不自动切换（自动切换等于在用户不知道的情况下花另一个账号的钱），只给一个「改用 {另一家}」按钮 |
| G8 下载导出 | 视频要放进导出包，key 不能出现在导出包里（PRD 8.12） |

## 需要 Lu 定的

**接入方式。** Higgsfield 必须经过服务器。可选：

- A：先只接火山（含 BytePlus 海外区），走浏览器直连。key 错时只能提示「检查密钥或网络」（E4）。Higgsfield 等以后有服务器再接。不改范围。
- B：两家都经过本地 `server/` 转发。在 Lu 的电脑上能用，但 key 会经过本机的 `server/`，和「密钥直接发给服务商、不经过别处」的文案以及 2026-10-23 的决定都冲突。真正给用户用的话还是得部署服务器，属于超出范围的事。
- C：只接 Higgsfield，经过本地 `server/` 转发。问题同 B。

PM 推荐 A：生成视频的功能本身还在 Backlog，没必要为它先搭一个转发层。
